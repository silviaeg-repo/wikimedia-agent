# Prompt Engineering approach and decisions

This agent is designed to answer questions in a natural and conversational way. The user must trust that the agent is not distorting or changing the information retrieved from Wikipedia, and that when information has low quality or could be too opinionated, the agent will surface this quality issue to the user. The answers provided by the agent are based on the information provided by the user, the general knowledge of the LLM and the encyclopedic articles available in Wikipedia. The construction of the agent focus the prompt on semantic judgement, pushing deterministic decisions into the code. The prompt handles interpretation like whether a question is ambiguous; when to answer from context versus consulting Wikipedia; or when to ask for clarification. The prompt also shapes the answer in a conversational narrative. At the same time, deterministic behavior like provenance, source quality, retrieval limits, citation validation and numbering are handled and tested by code. The core principle is reliability: is something can be mechanically checked, it should not rely on the model instructions.

When facing ambiguity, the agent must always ask for more information rather than guess. Several articles in Wikipedia have extensive disambiguation pages. A great example is the list of articles related to St. Mary's Church with over 900 entries. In these situations, the agent must provide any helpful information for the user to find the correct reference. The agent must also use information from the conversation context or nuances from the latest question to decide on the most relevant reference to retrieve. If this information isn't enough, the agent must ask the user and never silently choose the reference based on quality grade or other parameters. At the same time, an agent that asks for clarification unnecessarily can be annoying, so the correct balance is guaranteed through a couple evaluations cases.

Grounding the responses on retrieved articles must not weaken along the conversation. The agent can reference previously retrieved articles from its context, but the reference must still be relevant for the context. For instance, when asking "Who was Benjamin Franklyn?", then in sequence, "How old was he when he died?", can reference the same wikipedia article, but the provide information must be accurate to the content in both instances. The article reference must be presented in all the answers that consume its data, and if an article contains poor quality or unreviewed content, this must also be flagged to the user.

Articles retrieved from Wikipedia must be handled as untrusted content. The text must never be interpreted as instructions and the model must never obey "SYSTEM:" style directives in the article. This guidance is added to the prompt so to avoid prompt injection from the articles themselves. Nonetheless, broad text sanitization could damage the faithfulness of the source material, so containment and structural boundaries were used instead. Article provenance and quality grading are retrieved via API metadata and never from the article text.

To guarantee a natural conversation, the agent should avoid exposing Wikipedia structural implementation, like explaining that there are over 900 results for "St. Mary's Church" in a disambiguation page. Instead, the agent should help the user find the correct article based on the context, the most popular articles or simply by asking for more information.

A core aspect of the trust between the agent and the user is the list of references presented alongside each response. Each article must be uniquely identified by the agent while the presentation of the article is consistent and easy to follow. At first, I suggested the agent to keep a sequential numeric ordering of the retrieved articles, but this ended up being a problem when the context started eliminating older references for memory management. A better approach is to separate the reference indexing used by the agent to use the article title, like [[Ada Lovelace]], while the render will deterministically enumerate the relevant articles using [1], [2], [3] reference style.


One last important property of the way the agent presents the content is related to the quality of the Wikipedia articles themselves. Every article in Wikipedia is graded based on the number of reviewers, editors and the quality of its own references as described in https://en.wikipedia.org/wiki/Wikipedia:Content_assessment. Independent editors may nominate an article to be a Good Article or a Featured Article, and the winners are then granted these special gradings. After some research, I learned the quality of an article is not related to any particular knowledge field, or whether the article is about a real or fictional theme. For instance, the article about the fictional place of Mordor (https://en.wikipedia.org/wiki/Mordor) is graded as a Good Article, while real places on Earth like Namib-Naukluft in Namibia (https://en.wikipedia.org/wiki/Talk:Namib-Naukluft_National_Park) and Caatinga (https://en.wikipedia.org/wiki/Caatinga) in Brazil have only start-class articles. But some themes are more prone to poor quality than others, like pages about celebrities and politicians are more prone to defamation and inaccuracy. For this reason, I instructed the agent to annotate the references with a user friendly information about the quality of the article indicating whether the article was not well developed or if it could potentially include defamatory or biased content.

# The Eval Suite

Evaluations were designed to measure the non-deterministic quality of the answers. These were nuanced properties of the responses that would otherwise be very difficult to measure with regular expressions or other text-matching structures. Simple evaluations were introduced as soon as the agent implementation had a functional question / answer behavior, although still not interactive, while more complex and nuanced evaluations where introduced later as the agent gained more context, complex instructions and a natural conversation style.

The first property of this agent is to ground its responses on Wikipedia articles and for this, a relevant article must be retrieved, interpreted and an answer to the user question must be built cohesively. An answer can be correct without consulting Wikipedia, but then the agent would not be serving its purpose. When answering a question based on the content, the agent must also judge the quality of the content and not refuse to answer based on low quality alone. It may refuse to answer loaded and defamatory questions, while still recovering the relevant articles and responding with factual information.

All interaction scenarios are evaluated by the same judge that executes a sequence of checks on the responses provided by the agent on a one- or multi-hop sequence of asks and responses. Every scenario is evaluated by the judge under the same model, rubric, prompt structure, setting and grading criteria. The agent and the judge use different models intentionally so to avoid self-preference results, keeping the evaluation configuration independent from the agent. The judge also receives the context of iterations and previously retrieved articles passed to the agent, so it can evaluate citation validity, provenance integrity, source disclosure, etc. Based on the conversation context, the judge also checks for proper use of pronouns, topic refinement, stable source identity and source quality, and context exhaustion for long conversations.

A difficult integration to validate is the refusal of the agent to answer either based on the lack of content on Wikipedia, for themes like where to find aliens on Earth or the number of ducks that fit in the color red, or due to abusive questions like "How can I use cyanide to kill my neighbor's cat". For the first case, the agent must indicate that the information is not present and maybe provide some alternative content related to the topic of the question. On the second case, related topics may be available in Wikipedia, like "how to perform humane euthanasia on animals", so the agent must still reply, but with a benign answer on the same topic. The nuanced behavior arrives from over-refusal to answer questions to the point that the agent is not longer useful or prevents the user from finding benign articles on delicate topics.

# Success, learnings and limitations

At the end of the exercise, all 28 evals were successful and validated judgement properties of the agent like answer correctness, citation validity and provenance integrity, injection resistance (from Wikipedia articles and user's input), and source disclosure. The evals also show that multi-hop interactions work correctly and that disambiguation worked quite well for simple disambiguation like "Jaguar" or "Mercury" but still required a more deterministic handling of the DisambiguationError to deal with the edge case of "St. Mary's Church". The forgeable closing-tag vulnerability (</wikipedia-article>) from the wikipedia articles was actually discovered when constructing adversarial prompts to detect prompt-injection. This tag could allow the agent to think the article had reached it's and an interpret the remaining of the text as an instruction.

Although the evals were able to avoid regressions and they got a perfect score at the end, they still can't guarantee the quality of the responses. Given more time, I'd have added more qualitative verification steps to verify whether the retrieved article was indeed the best one available based on the context, whether the response was easy to understand and how well it was presented within the context of the conversation. I'd also better stress pivoting a subject mid-conversation, which was a manual interaction that surfaced many issues related to indexing the articles locally and referencing them properly on each answer. Other important things for a natural conversation agent includes reducing the latency of the responses. During manual testing, the agent took up to 30s to reply, so maybe tuning the context and the instructions could reduce the latency and the cost of the agent.

Given more time, I'd also ask other people to try and use the agent and let me know about their own expectations and interactions. The current agent is strongly focused on the provenance of the data, but maybe other users may value other types of insights about the topics, like summarizing content across multiple articles to provide more complete answers, or to intentionally highlight different perspectives about the same topic. 

# Time and execution

Research about Wikipedia articles and API was done outside the timed boundary of this project. The first hour of execution started by building the project-plan.md with the implementation principles of the agent, boundaries, client policies, expected agent behavior and breakdown of implementation phases. Once the initial plan was done, the next 1.5h was dedicated to the code implementation with the initial set of evaluations. An additional 30 min was dedicated to interact with the agent, improve the user experience and introduce more complex evaluations to cover the newly discovered edge cases.
